# Prompt 模板 A–D

> 用法：复制对应模板到投喂文件（如 `R1-prompt-codex.txt` / `R2-brief-claude.txt`），替换 `<>` 占位符后经 **stdin** 投喂（`- < f` / `cat f | claude -p`）。长 prompt **不要塞命令行参数**——会截断/乱码（坑清单）。

## 模板 A：R1 独立红队审查（每轮审查的起点）

```
你是**独立的对抗性审查员（红队）**。你与方案作者（<方案作者代号>）以及其他审核方彼此独立。你的任务不是复述或赞美文档，而是**尽力证伪它**。默认立场：每个结论都可能是错的，直到你用一手证据亲自验证过。**你不需要同意其他审查员的看法。**

## 审查目标
- 被审主文档：`<相对路径>`（项目根 `<绝对路径>`）
- <若已有前一轮审查，给出 REVIEW 文档路径，并要求审查"作者对它的复核是否正确">

## 你必须独立核验的内容
**A. 行号与符号引用**：<列出文档引用过的 文件:行号 清单>——逐条开文件核对
**B. 数据取证**：<数据位置；打开方式（sqlite 必须 mode=ro）；解释器绝对路径；列出文档所有数字要求逐个复算>
**C. 逻辑与因果对抗（核心）**：
 1. <逐条要求构造反例或替代解释>
 2. 有没有**比文档更直接**的解释能同时解释现象？
 3. 文档的"唯一性"断言（如"唯一没办法靠前端补的一条"）成立吗？
**D. 审查前一轮审查**：它有没有过度指控/行号幻觉/把推测写成定论？作者对它的"驳回"是否正确？
**E. 落地核验（易被忽略，实测抓到过重大问题）**：文档/处置清单声称"已修订"的条目，**逐条回读源文件验证**，输出"已落地 / 未落地"表。**不要相信任何"编辑成功"的回执**——回执不代表文件里有。
**F. 符号引用一致性**：文档里出现的**函数名/类名**，逐个 grep 确认它真的定义在该处（实测抓到过"把 `:830` 所在函数写成 `_execute_node`、实为 `_run_node`"这类笔误，两位审核员都漏了）。
**G. 修复建议可行性**：<逐条问真能达成目标吗？有没有被忽略的代码路径/分支？顺序约束是否成立？>

## 硬性约束
- **只读**：绝不修改/创建/删除仓库文件；不重启服务。中间脚本写系统临时目录，不落仓库。
- **独立性隔离**：除本 prompt 明确列出的文件外，仓库内其他一切审查产物（`R*-*.md`、`REVIEW-*.md`、`_codex_*`、`_claude_*`、`smoke.*`）一律无视，不得读取、不得引用为证据——你的结论只能来自你自己的核验。
- 每条判定必须附**可复现证据**（`文件:行号`+原文片段，或 SQL+实际返回）。禁止凭印象。
- **无法核验必须明写"无法核验"并说明原因**，严禁猜测，严禁用"可能/大概"冒充结论。
- 区分「确证」与「推测」；若被审文档把推测写成定论，明确指出。
- 不要复述原文凑篇幅；只写核验结果与异议。

## 输出
1. 总体裁决（每个结论：成立/部分成立/不成立 + 可信度）
2. 断言核验表：`| # | 断言 | 文档位置 | 我的独立核验 | 判定 | 证据 |`
3. 对作者复核表的审查（若适用）
4. 对前一轮审核方结论的审查
5. 我发现的、文档都没提到的问题
6. 修复建议可行性审查
7. 问题清单（阻断/严重/一般/吹毛求疵）
8. 本次审查的局限

现在开始：先读文档，再逐条自己动手核验。
```

### 每家微调（追加到硬性约束）

- **codex**：`本机可用 shell 是 PowerShell，不是 Bash；Git Bash 残缺（head/tail/dirname 不可用），命令输出请转存文件后再读。`
- **claude**：同上，并追加 `你的 shell 工具名以实际可用为准。`

## 模板 B：Rk 交叉质询 brief（**本轮次讨论的灵魂**）

```
这是第 <k> 轮（共 <N> 轮）。你是审核方：<你的代号>。
你对本主题的上一轮结论，已被另一位审核员 <对方代号> 与方案主持人（我）分别审阅。
**本轮目标不是重新审一遍**，而是：对下面的异议逐条表态，并回答我指定的问题。
**只处理分歧点，不要重述已达成共识的内容。**

## 一、另一位审核员 <对方代号> 对你结论的异议
<逐条列出：它质疑你的哪一句 / 它的理由 / 它给的证据（文件:行号 或 SQL 结果）>
1. ...
2. ...

## 二、我对你结论的裁决（含我的独立复核证据）
| 你的结论 | 我的独立复核 | 裁决 |
|---|---|---|
| ... | `文件:行` + 实测 | 采纳 / 部分采纳 / 驳回 |

我驳回你的条目及理由：...

## 三、本轮请你只回答以下问题
Q1. 对第 1 条异议，你**维持原判还是修正**？若维持，必须给出**新证据**（重复上一轮的说法不算）。
Q2. 我驳回你的那一条，你是否接受？若不接受，请指出我的复核错在哪里。
Q3. <针对尚未收敛的具体技术分歧，逐条列出>

## 四、硬约束
- 只读；不改/不建/不删仓库文件；中间脚本写系统临时目录
- 每条表态必须附可复现证据
- **维持原判但拿不出新证据的，请直接写"无新证据，撤回"** —— 这比硬撑更有价值
- 无法核验必须明写；不要复述文档原文

## 五、输出格式
1. **逐条表态**：`| # | 对方异议 | 我维持/修正/撤回 | 证据 |`
2. **对我裁决的回应**：`| 我被驳回的结论 | 接受/不接受 | 理由+证据 |`
3. **新增异议**（对另一方或对我的）
4. **剩余分歧点清单**（你认为仍未解决的）
5. **本轮我的局限**
```

## 模板 C：终局确认（可选，用于 N 轮后收口）

```
这是收口轮。下面是本轮已达成的**全部共识**与**剩余分歧**。
请你只回答三件事，不要重新展开审查：
1. 共识清单中，有没有哪一条你其实**不同意但没说**？（有则指出是哪条 + 理由）
2. 剩余分歧里，有没有哪一条你认为**已可判定**？（给判定 + 证据）
3. 是否存在**阻断级**问题尚未被登记？（有则列出，无则写"无"）
```

## 模板 D：预算/超时中断后的**收口续接**（resume 专用，很省钱）

> 场景：审核方跑到一半被 `--max-budget-usd` / 超时掐断，但取证进度都在会话里。**不要重跑**，resume 收口。

```
【重要：预算中断收口】

上一轮因为客户端预算上限（或超时）被强制中断，不是你出错。你的取证进度都还在。

现在请**立即收口**，不要再展开新的取证：
1. **停止**继续深挖（最多允许再读 1-2 个文件做补充核对）。
2. 基于你**已经完成核验**的内容，直接输出最终审查报告。
3. 未核验的清单项**必须明确标注「未核验（因预算中断）」**，不要凭印象补写、不要推测。
4. 报告结构沿用原始要求。
5. 已核验的每条判定仍必须附 `文件:行号` 或 SQL 证据。

请现在直接输出报告，作为你的最终消息。
```
